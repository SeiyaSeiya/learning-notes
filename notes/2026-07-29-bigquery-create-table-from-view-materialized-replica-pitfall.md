# BigQueryでビューからテーブルを新規作成しようとして「マテリアライズド ビューのレプリカ作成」画面に迷い込んだ話

## 概要
- **学んだきっかけ**: あるデータセット内のビューを元に、別のデータセットへ通常のテーブルを新規作成しようとした作業。Explorerパネルからビューを開いて「テーブルを作成」を選んだところ、想定と違う設定画面（マテリアライズド ビューのレプリカ作成）が出てきて戸惑った。
- 過去にも同様の作業（ビュー→テーブル化＋定期反映）を行っており、[2026-07-18のメモ](2026-07-18-bigquery-view-table-and-scheduled-query.md)に手順を残していたことを思い出し、そちらの方針（空テーブル作成→スケジュールクエリで定期反映）を踏襲することにした。

## 1. 遭遇した問題：テーブル作成ダイアログのはずが「レプリカ作成」画面だった

BigQueryコンソールで、あるビューに対して「テーブルを作成」を選択したところ、通常のテーブル作成ウィザード（空のテーブル／既存テーブル・ビューからのコピーなどを選べる画面）ではなく、以下のような項目を持つ画面が表示された。

- ソース側の「プロジェクト」「データセット」「表示（ビュー名）」
- 「既存のビューが複数のデータセットを参照している場合は、CREATE MATERIALIZED VIEW AS REPLICA DDL ステートメントを使用して、レプリカのマテリアライズド ビューを作成してください」という注意書き
- 送信先の「レプリカのマテリアライズド ビューの名前」欄

これは通常の「テーブルを作成」ではなく、**マテリアライズド ビューのレプリカ（別データセット／別リージョンへの複製）を作成する画面**だった。

## 2. 原因

参照元のビューが複数のデータセットにまたがってデータを参照している構成だったため、UIが「単純なコピーではなく、マテリアライズド ビューのレプリカ作成のDDLを使ってほしい」という案内を出したもの。単に「ビューの中身を今の状態でテーブルとして欲しい」という目的とは異なるフローに入り込んでしまっていた。

## 3. 目的に応じた2つの選択肢

### (a) 一度きりのスナップショットで良い場合：CTAS

クエリエディタで`CREATE TABLE ... AS SELECT`（CTAS）を実行するのが最も簡単。

```sql
CREATE TABLE `プロジェクト.宛先データセット.テーブル名` AS
SELECT * FROM `プロジェクト.元データセット.ビュー名`
```

ただしこれは実行した瞬間のスナップショットを1回作るだけで、以後の自動更新はされない。

### (b) 継続的に内容を反映し続けたい場合：空テーブル＋スケジュールクエリ（トリガー）

BigQueryには従来型DBのような「トリガー」機能は無いため、定期反映にはBigQuery Data Transfer Serviceの「スケジュールクエリ」を使う。この方式の詳しい手順（作成手順・書き込み設定の種類・権限の注意点など）は[2026-07-18のメモ](2026-07-18-bigquery-view-table-and-scheduled-query.md#7-スケジュールクエリトリガー)に整理済み。

大まかな流れ：

1. 宛先となる空のテーブルを（スキーマを固定したい場合などに）先に作成
2. クエリエディタで`SELECT * FROM ビュー`を記述して実行
3. 「スケジュール」から「新しいスケジュールされたクエリを作成」し、頻度・宛先テーブル・書き込み設定（追加／上書き）を指定

## 4. 今回採用した方針

複数データセットを参照するビューだったため(a)のCTASでは要件を満たしにくく、また過去の同種の作業でも(b)の方式（空テーブル作成→スケジュールクエリで定期反映）を採用していたことを思い出したため、今回も同じ方針を踏襲した。実際にクエリを実行し、「スケジュール」からスケジュールされたクエリを作成して「スケジュールされたクエリが作成されました」の通知を確認できた。
