# ターミナルの文字列をマウスなしでコピーする方法

## 概要
`pwd`の出力などをマウスのドラッグ&コピーで取得していたが、この操作が煩わしかったため、キーボードのみでコピーする方法を調べた。「コマンドの出力結果」と「ターミナル上の任意の文字列（過去の出力・エラーメッセージなど）」で対処法が異なる。

## 使用しているターミナルの確認方法
以下のコマンドで、現在使っているターミナルアプリを確認できる。

```bash
echo $TERM_PROGRAM
```

| 出力 | ターミナル |
|---|---|
| `Apple_Terminal` | Terminal.app（macOS標準） |
| `iTerm.app` | iTerm2 |
| `vscode` | VS Codeの統合ターミナル |

→ 自分の環境は **Terminal.app**（メインで使用）と **VS Codeの統合ターミナル**の2種類だった。

## パターン1: コマンドの出力結果をコピーする
出力をそのままクリップボードに送る `pbcopy` を使うのが最も簡単。マウス操作は不要。

```bash
pwd | pbcopy
```

任意のコマンドの標準出力をパイプでつなげば同様にコピーできる。

```bash
which python3 | pbcopy
```

よく使うなら、`.zshrc`に関数を定義しておくと「表示 + コピー」を同時にできる。

```bash
pwdc() {
  pwd | tee /dev/tty | pbcopy
}
```

## パターン2: 出力以外の任意の文字列をコピーする
すでに画面に表示されている文字列（エラーメッセージ、過去のコマンド出力など）をコピーするには、ターミナル側に「キーボードで選択できる仕組み（コピーモード）」が必要。Terminal.appにはこの機能がなく、VS Codeの統合ターミナルにも同等のvimライクな操作はない。そのため、選択肢は次の2つ。

### 方法A: tmuxを使う（推奨・Terminal.appでもVS Codeターミナルでも同じ設定で使える）
tmuxはターミナルアプリの中で動く別レイヤーなので、どのターミナルアプリの上でも同じ操作感でキーボードのみコピーできる。複数のターミナルアプリを使い分けている場合に効率的。

インストール:
```bash
brew install tmux
```

`~/.tmux.conf`に追加:
```
set -g mode-keys vi
bind -T copy-mode-vi v send -X begin-selection
bind -T copy-mode-vi y send -X copy-pipe-and-cancel "pbcopy"
```

使い方:
1. `tmux`でセッションを開始
2. `Ctrl+b [` でcopy-modeに入る
3. `h` `j` `k` `l` で移動、`/` で文字列検索
4. `v` で選択開始 → 移動して範囲選択
5. `y` でmacOSのクリップボード（pbcopy）にコピー

SSH先のリモートサーバー上のtmuxでも同じ設定で使えるため、ローカル/リモートを問わず一貫した操作にできるのが利点。

### 方法B: iTerm2に乗り換える
iTerm2は最初からCopy Mode（`Cmd+Shift+C`）を搭載しているため、設定なしで使える。
- `Cmd+Shift+C` でCopy Modeに入る
- `h/j/k/l`で移動、`w/b`で単語移動
- `/` で検索
- `Space` で選択開始
- `Enter` でクリップボードにコピー

tmuxの設定が不要な分、導入は簡単。ただしVS Codeの統合ターミナルを使う場面ではこの機能は使えない（iTerm2固有の機能のため）。

## まとめ・使い分け
| 状況 | 方法 |
|---|---|
| コマンドの出力だけをコピーしたい | `pbcopy`にパイプ |
| Terminal.app / VS Codeターミナルの両方で同じ操作にしたい | tmux + `copy-pipe-and-cancel "pbcopy"` |
| Terminal.appだけ使っていて手軽に済ませたい | iTerm2に乗り換えてCopy Modeを使う |
| SSH先のリモートサーバーでも同じ操作をしたい | tmux（ローカルにインストールされていなくてもリモート側にあればOK） |
