# Claude Codeの「フォーク」機能とは何か：追加時期と使い方

- 学んだきっかけ: Coworkとの会話で「Claudeのフォーク機能はGitのフォークに似ていて便利そう」という話題になり、実際にはどういう機能で、いつ追加されたのかを調べた。

## 1. 「フォーク」とは何か（Gitのフォークとは別物）

- Gitのフォーク（リポジトリを複製して独立させる）とは違い、Claude Codeのフォークは「今までの会話・セッションをそのまま複製するサブエージェント機能」。
- 通常のサブエージェント（`general-purpose`など名前付きのもの）は毎回ゼロから文脈を渡す必要があるが、フォークは今の会話全体（システムプロンプト・使えるツール・モデル・メッセージ履歴）を丸ごと引き継いだ状態でスタートする。背景説明が不要な点が最大の特徴。
- フォーク側のツール呼び出しは元の会話には表示されず、最終結果だけが本体の会話に戻ってくるので、メインの文脈（コンテキストウィンドウ）を汚さずに済む。
- 使いどころ: 名前付きサブエージェントに頼むには背景説明が多すぎるような差し込みタスク、または同じ出発点から複数のアプローチを並行して試したい場合。

## 3. 使い方の概要

- `/subtask <タスク>`: 会話内でフォーク型サブエージェントをその場で起動する。プロンプト下のパネルに行が追加され、バックグラウンドで走りながら本体の作業を続けられる。完了すると結果がメイン会話にメッセージとして届く。
- `/fork`: 会話全体を新しいバックグラウンドセッション（`claude agents`で別行として見える、独立したセッション）としてコピーする。エージェントビューが無効な設定では代わりに`/subtask`と同じ動作になる。
- パネル操作: `Enter`で選択中のフォークのトランスクリプトを開き、追加のメッセージを送れる。`x`で完了したフォークを消す、または実行中のフォークを停止できる。
- Claude自身に`fork`というサブエージェント種別を明示的に指定させ、Claudeの判断で自律的にフォークを起動させることも可能（実験的機能）。この場合`isolation: "worktree"`を指定すると、フォークのファイル編集は別のgit worktreeに書き込まれ、自分の作業ツリーには影響しない。
- コスト面: フォークはシステムプロンプト・ツール定義が親と完全に同一なので、初回リクエストで親のプロンプトキャッシュを再利用できる。同じ文脈が必要なタスクなら、新規サブエージェントを立てるより安く済む。
- 制約: フォークはさらに別のフォークを生成できない（1段階まで）。
- 制御用の環境変数`CLAUDE_CODE_FORK_SUBAGENT`: `1`で明示的に有効化、`0`で（サーバー側のロールアウトを含め）完全に無効化できる。

## 4. まとめ

- Gitのフォークとは名前が同じだけで概念は別。「会話をコピーして差し込みタスクや並行検証をやらせる」ための機能。
- 2026年4月に実験的機能として登場し、6月にデフォルト有効化、7月に`/subtask`（会話内起動）と`/fork`（別セッションへの複製）の2コマンドに整理された、というのが現在の姿。
- 使い分けの基本: 本体の作業を続けながら裏で別タスクを進めたいなら`/subtask`、会話全体を丸ごと分岐させて別セッションとして扱いたいなら`/fork`。
