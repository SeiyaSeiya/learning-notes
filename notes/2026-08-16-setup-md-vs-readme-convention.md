# SETUP.mdとREADME.mdの違い、そしてSETUP.mdという慣習の位置づけ

- 学んだきっかけ: とあるGASプロジェクトのリポジトリに`README.md`と`SETUP.md`の2つのドキュメントがあるのを見て、両者の役割の違いと、`SETUP.md`というファイルがいつ・どういう経緯で使われ始めたのか気になった。

## README.mdは特別扱いされる「準標準」ファイル

`README.md`は歴史が長く（Unix文化の慣習として1970年代から存在し、GNU Coding Standardsでも言及されている）、GitHub/GitLab/npmなどのツールが「リポジトリ直下に置くと自動でトップページにレンダリングする」という特別扱いをする、事実上の標準ファイル。

## SETUP.mdにはそうした標準化された地位がない

`SETUP.md`はツール側の特別な扱いを一切受けない、ただの慣習的なファイル名。「READMEに全部書くと長くなりすぎるので、概要・背景（README）とインストール／セットアップ手順を分離する」という実務上の工夫として自然発生的に生まれたもので、明確な起源・誕生日があるわけではない。同じ役割を担うファイルには他にも

- `INSTALL.md`（GNUプロジェクトの慣習でより古くから存在する）
- `docs/setup.md`
- `CONTRIBUTING.md`内のセットアップ節

などのバリエーションがあり、どれを採用するかはプロジェクト・チームの流儀次第。

## 実プロジェクトでの役割分担の例

このリポジトリでは両ファイルが同じコミットで同時に生まれていたが（後から分割されたわけではない）、内容は最初からきれいに役割分担されていた。

- **README.md**: 「なぜこの仕組みが必要か」「何をするものか」という背景・設計判断を説明する文書。一度書けば大きく変わらない「なぜ」の記録。
- **SETUP.md**: 「実際に手を動かして展開するには何をすればいいか」という手順書。Script ID一覧・作業順序に加えて、各手順が完了/未対応かの**進捗管理表**まで持っている。展開が進むにつれて更新され続ける、状態を持つ運用ドキュメント。

## まとめ

- README.mdは歴史・ツールサポートのある準標準。SETUP.mdは標準ではなく、「概要」と「手順」を分離したいという実務上のニーズから生まれた慣習的な命名で、特定の誕生日はない。
- 迷ったら「一度書けば変わらない背景・why」はREADME、「実行手順・進捗など変化し続ける情報」は SETUP（またはINSTALL/docs配下）、という切り分けが実務的に使いやすい。
