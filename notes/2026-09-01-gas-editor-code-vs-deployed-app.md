# GASで「エディタ上のコード」と「デプロイしたアプリ」が別々になっている理由と、デプロイし忘れの弊害

- 学んだきっかけ: GASの基本的な疑問として、なぜデプロイしたWebアプリとエディタ上のコードが別々に管理されているのか、デプロイしないと（あるいはデプロイし忘れると）何が起きるのかをClaudeに質問した。[2026-08-27: GASプロジェクトの外部公開の仕組みとclaspでのデプロイ操作](2026-08-27-gas-external-publish-webapp-api-library.md)で調べた「デプロイの仕組み」そのものについて、より基礎的な「なぜそう設計されているか」を整理したメモ。

## 1. エディタのコードとデプロイは「作業ツリー」と「リリース済みバージョン」の関係

- エディタ上のコードは常に「今書いている最新の状態」。
- Webアプリや実行可能API・アドオンなど、外部からアクセスできる「デプロイ」は、デプロイした瞬間のコードのスナップショット（バージョン）に固定される。
- Gitに例えると、エディタが作業ツリー、デプロイがタグを打ってリリースしたバージョンに近いイメージ。

## 2. なぜあえて分離されているのか

外部から使われているアプリ（Webhookの受け口や、他の人が使っているWebアプリのURLなど）が、開発者がコードを書き換えている最中に急に挙動を変えたり、書きかけのバグだらけのコードで動いてしまったりするのを防ぐため。

- デプロイを分けておけば、エディタでどれだけ試行錯誤しても本番で動いているバージョンには影響しない。
- 準備ができた時点で「新しいバージョンとしてデプロイ」して初めて、変更が本番に反映される。
- 新しいデプロイで問題が起きても、古いバージョンに戻す（ロールバック）ことができる。

この「常にエディタの最新コードと同期するヘッドデプロイ（テスト用）」と「特定のバージョンに固定される本番用デプロイ」の2種類がある点は、[2026-08-27のメモ](2026-08-27-gas-external-publish-webapp-api-library.md)で触れたのと同じ仕組み。

## 3. デプロイしない／再デプロイし忘れると起きる弊害（具体例）

### 例1: コードを直したのに本番に反映されない

GASでWebアプリを作り、LINEのWebhookや問い合わせフォームの送信先として使っているケース。

1. 最初に「ウェブアプリとして導入」してURL（`https://script.google.com/macros/s/.../exec`）を発行し、外部システム側にそのURLを登録する。
2. その後`doPost()`のバグをエディタ上で修正して保存しても、それだけでは本番のWebアプリには反映されない。既存のデプロイは修正前のバージョンに固定されたままなので、Webhook経由のリクエストは相変わらず古い（バグのある）挙動のまま。
3. 「エディタでは直したはずなのに、実際に使うと直っていない」という混乱が起きる。
4. 反映させるには「デプロイを管理」から該当デプロイを選び「新しいバージョン」で再デプロイする必要がある（clasp運用の場合は`clasp deploy -i <既存のdeploymentId>`。`-i`を付け忘れると別URLが新規発行されてしまう点は[2026-08-27のメモ](2026-08-27-gas-external-publish-webapp-api-library.md)の「6. 実務上の注意」を参照）。

### 例2: そもそも外部からの入り口が存在しない

Webアプリ・実行可能API・アドオン・ライブラリは、一度も「デプロイ」していなければURLやAPIとして公開されず、外部のシステムやユーザーからは一切呼び出せない。エディタ上でどれだけ完成度の高いコードを書いても、デプロイしない限りそれは「自分だけがエディタの実行ボタンで動かせるスクリプト」のまま。

## 4. デプロイの固定が関係しないケース

時間主導型トリガー（毎日◯時に実行、など）や、スプレッドシートの`onEdit`のような単純トリガーは、この「デプロイの固定」の対象外で、常にプロジェクトに保存されている最新のコードで実行される。

デプロイの固定が関係してくるのは、主にWebアプリ・実行可能API・アドオン・ライブラリのように「外部から呼ばれる公開された入り口」を持つケースと整理すると分かりやすい。

## まとめ

- GASがエディタコードとデプロイを分離しているのは、外部から使われているアプリの挙動を開発中の編集から守り、公開タイミングを開発者が制御できるようにするため。
- Webアプリなどを一度デプロイした後にコードだけ直しても、再デプロイ（新しいバージョンとしてのデプロイ、既存デプロイなら`-i`付きの更新）をしない限り本番には反映されない。これがGAS運用でよくハマるポイント。
- そもそもデプロイしていなければ、Webアプリ・実行可能API・アドオン・ライブラリとしての外部からの入り口自体が存在しない。
- 一方、時間主導型トリガーや単純トリガー（`onEdit`など）は常に最新の保存済みコードで動くため、この分離の影響を受けない。
