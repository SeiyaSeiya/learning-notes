# Googleドライブをgitのリモートリポジトリ代わりに使う方法（ベアリポジトリ運用）

- 学んだきっかけ: 9/29、開発部と違いCREにはGASコードを管理するGitHubリポジトリが無く、複数メンバーでのバージョン管理ができていなかった。代替としてGoogleドライブをgitのリモートにできないか検討し、実際に共有フォルダ内にベアリポジトリを作成してpush・cloneまで動作確認した。

## 1. 結論：Googleドライブは「gitサーバー」ではないが、同期フォルダ経由でリモート代わりにできる

- Googleドライブのプランでは、GitHubのようにgitのネットワークプロトコル（push/pull）を直接受け付ける仕組みは無い。
- ただし「Google Drive for Desktop」で自分のPCにマウントされる同期フォルダは、gitから見ればただのローカルファイルパスなので、その中に**ベアリポジトリ**を置けば、通常のgitコマンド（`git remote add` / `git push` / `git clone`）がそのまま使える。実体としては「Drive同期の仕組みを使って、ローカルパス経由でリポジトリを共有している」状態。
- Google Drive APIを直接叩く専用のgitリモートヘルパー（`git-remote-drive`、`git-remote-gdrive`等のOSS）も調査したが、調べた時点では「pushが未実装」「star・テスト実績がほぼゼロ」など実運用に耐える状態ではなかったため、今回は同期フォルダ方式を採用した。

## 2. ベアリポジトリとは

- 作業ファイル（`.gs`や`.js`などの実ファイル）を持たず、gitの履歴データ（`.git`の中身）だけがトップレベルに直接展開されたリポジトリ。`git init --bare xxx.git`で作成する。
- 普通のリポジトリで複数人が同時にpush/pullすると、作業ファイルの衝突やチェックアウト中ブランチとの競合が起きうる。ベアリポジトリは作業ファイルを持たないためこの問題が起きず、「複数人が安全にpush/pullできる共有の置き場所」として機能する。GitHub/GitLabがサーバー側で管理している実体も基本的にこれと同じ。

## 3. セットアップ手順

1. Google Drive for Desktopを各メンバーのPCにインストールし、組織のGoogleアカウントでログインする。
2. マイドライブ上に共有フォルダ（例: `gas-repos`）を作成し、メンバーを「編集者」権限で共有する。
3. 同期フォルダ内でベアリポジトリを作成する。

   ```bash
   cd "/Users/<username>/Library/CloudStorage/GoogleDrive-<組織アカウント>/マイドライブ/gas-repos"
   git init --bare gas-project.git
   ```

   直後はDrive側の同期が終わっていないことがあるので、メニューバーのDriveアイコンで同期完了を確認してから次に進む。

4. 既存のローカルリポジトリにリモートとして登録し、最初のpushを行う。

   ```bash
   cd ~/Projects/gas-project
   git remote add origin "/Users/<username>/Library/CloudStorage/GoogleDrive-<組織アカウント>/マイドライブ/gas-repos/gas-project.git"
   git push -u origin main
   ```

5. 他のメンバーは、同期完了を確認した上で、自分のPC上の同期フォルダパスからcloneする。

   ```bash
   git clone "/path/to/GoogleDrive/gas-repos/gas-project.git" gas-project
   ```

- パスにはOSやアカウントによって半角スペースを含む部分（Macなら`My Drive`、Windowsなら空白入りの共有フォルダ名など）が出てくるため、`git remote add`や`git clone`のパスは常にダブルクォーテーションで囲む。クォーテーション無しだとシェルがスペースを引数の区切りとして解釈し、パスが分割されて渡ってしまう（これはgit特有の話ではなく、パスを引数に取る全コマンドに共通する挙動）。

## 4. 複数プロジェクトを1つの共有フォルダにまとめる

- `gas-repos`はGitHubで言う「Organization」に相当する入れ物として扱い、この中に複数のベアリポジトリを並べて置ける。

  ```
  gas-repos/
  ├── project-a.git/
  ├── project-b.git/
  └── project-c.git/
  ```

- 各プロジェクトがもともと別々のローカルgitリポジトリなら、手順3〜5をプロジェクトごとに繰り返すだけでよい。
- もし複数プロジェクトが1つのローカルリポジトリに同居している（モノレポ）場合は、無理に分割せず、ベアリポジトリも1つのままでよい。履歴を分けたい場合のみ`git filter-repo`等でのサブフォルダ切り出しが必要になる。

## 5. 運用上の注意点（同時アクセスのリスク）

- Google Driveの同期はファイル単位のコピー同期であり、gitが前提とする「アトミックな書き込み」を保証しない。**2人以上がほぼ同時にpushすると、ref/objectファイルの同期タイミングがずれてリポジトリが壊れるリスク**がある。
- 対策として以下を徹底する。
  - 同時にpushしない（Slack等で「今からpushします」と一声かける運用にする）
  - push後はDriveの同期完了（同期アイコンのチェックマーク）を確認してから他メンバーに連絡する
  - 定期的に`git fsck`で破損の有無を確認する
  - 定期的にベアリポジトリ自体をzip等でバックアップする
- 同時アクセスのリスクを完全に避けたい場合は、ベアリポジトリではなく`git bundle create`で更新を1ファイルにまとめてDriveにアップロードし、各メンバーが`git pull xxx.bundle`で取り込む方式もある（手動作業は増えるが、同期途中の破損リスクは無い）。

## 6. ベアリポジトリの中身がGoogle DriveのWeb UI上で見えない理由

- ベアリポジトリの中身（`objects`、`refs`、`config`、`HEAD`等）はgit内部の管理ファイルであり、`.gs`/`.js`ファイルがそのままの形で入っているわけではない。
- コミットした内容は全て「オブジェクト」としてSHAハッシュ名のバイナリファイルに変換され、`objects/`配下に格納される。`git push`でまとまった量が送られた場合は、個別ファイル（loose object）ではなく`objects/pack/`配下の`.pack`（オブジェクト本体を圧縮してまとめたもの）＋`.idx`（索引）というペアに集約される。
- どちらも圧縮バイナリなので、Google DriveのWeb UIやFinder/エクスプローラーのプレビューで開いても意味のある内容としては表示されない。**これは正常な状態であり、失敗ではない。**
- 実際にコードの中身を確認したい場合は、別ディレクトリにcloneして展開するのが唯一の方法。

  ```bash
  git clone "/path/to/GoogleDrive/gas-repos/gas-project.git" /tmp/check-gas-project
  ls /tmp/check-gas-project
  ```

  実際にこの方法で`appsscript.json`や各`.js`ファイルが展開されることを確認済み。

## 7. Windowsメンバーへの案内方法

- Windows版Google Drive for Desktopは、マイドライブを「ドライブレター」（`C:`や`D:`のような1文字の記号でストレージを区別する仕組み。デフォルトは`G:`だが変更されている場合もある）としてマウントする。Macの`/Users/<username>/Library/CloudStorage/GoogleDrive-<組織アカウント>/...`という「フォルダ階層の一部」としての表現とは全く形式が異なる。
- Windows版の対応コマンド例（ドライブレターは環境によって異なるので、実際の値に読み替えてもらう必要がある）:

  ```
  git clone "<ドライブレター>:\マイドライブ\gas-repos\gas-project.git"
  ```

- 絶対パスをそのまま固定で伝えると、ドライブレターの違いで動かない人が出る可能性がある。そのため、以下のどちらかの案内方法の方が確実。
  1. **フォルダ内で直接ターミナルを開く**：エクスプローラー（Windowsのファイル管理アプリ。Macの「Finder」に相当）で`gas-repos`フォルダを開き、右クリック→「ターミナルで開く」（Git Bashなら「Git Bash Here」）。すでにそのフォルダの中にいる状態なので、絶対パスを意識せず相対パスでcloneできる：`git clone ./gas-project.git`
  2. **ドラッグ＆ドロップでパスを自動入力させる**：ターミナルに`git clone `とだけ入力した状態で、対象の`.git`フォルダをエクスプローラー（Macなら Finder）からターミナルの画面にドラッグ＆ドロップすると、クォーテーション付きの絶対パスが自動入力される。Mac・Windows両方で使えるので、OSを問わず同じ案内で説明できる。
- Macの「Finder」には、Windowsのエクスプローラーと違って「ターミナルで開く」が標準の右クリックメニューには入っていない。システム設定→キーボード→キーボードショートカット→サービス→「フォルダでターミナルを開く」を一度有効にすると、以後は右クリックから使えるようになる。

## まとめ

- Googleドライブは直接のgitリモートにはなれないが、「Google Drive for Desktopの同期フォルダ内にベアリポジトリを置き、ローカルパスとしてgitに登録する」ことで代用できる。
- 最大のリスクは複数人の同時push時のDrive同期の競合による破損なので、「同時にpushしない」「push後は同期完了を待つ」という運用ルールの徹底が必須。
- 将来的にCREでもGitHub/GitLab/Bitbucket等、正規のgitホスティングが使えるようになるなら、そちらに移行する方が同時アクセスの安全性の面で望ましい。今回のGoogleドライブ方式は、それが用意されるまでの代替手段という位置づき。
