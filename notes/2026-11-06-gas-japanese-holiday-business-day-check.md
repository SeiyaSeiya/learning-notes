# GASで土日に加えて祝日も判定する方法と、営業日判定を1つの関数に集約する設計

- 学んだきっかけ: GASで運用している定期実行の自動化処理で、「土日は投稿・リマインドしない」という判定が `getDay()` の直書きで3か所に散らばっていた。ここに祝日も加えたいと考え、祝日の判定方法と、判定ロジックの集約のしかたを整理した。

## 1. 祝日を判定する方法（3つ）

| 方法 | 概要 | 向いている場面 |
|---|---|---|
| Googleカレンダーの「日本の祝日」 | `CalendarApp` で祝日カレンダーを参照する | 通常はこれで十分。振替休日・国民の休日も含まれ、法改正による祝日の追加・変更もGoogle側で更新される |
| 内閣府の祝日CSV／公開API | `UrlFetchApp` で取得して判定する | カレンダー権限を増やしたくない、祝日名も欲しい場合。取得結果は `CacheService` やシートへ保存しておく |
| スプレッドシートに自前で一覧を持つ | シートの祝日リストを `Set` などで照合する | 年末年始・創立記念日などの独自休業日も扱いたい場合。ただし毎年の更新が必要 |

今回は1番目を選んだ。独自の休業日が必要になったら、3番目を併用する。

## 2. Googleカレンダーでの実装の要点

```javascript
const calendar = CalendarApp.getCalendarById('ja.japanese#holiday@group.v.calendar.google.com');
const events = calendar.getEvents(new Date(year, 0, 1), new Date(year + 1, 0, 1));
events.forEach(event => {
  const d = event.isAllDayEvent() ? event.getAllDayStartDate() : event.getStartTime();
  // d を 'yyyy-MM-dd' の文字列にして Set に入れておく
});
```

- 祝日は「終日イベント」として入っている。日付の取り出しは `getAllDayStartDate()` を使う。
- 照合用のキーは `Utilities.formatDate(date, 'Asia/Tokyo', 'yyyy-MM-dd')` のように、タイムゾーンを明示した文字列にそろえる（プロジェクトのタイムゾーン設定に依存しないため）。
- `getCalendarById` は、取得できないと `null` を返すことがある。`null` チェックを入れておく。

### 「サービス」への追加は不要
`CalendarApp` は `SpreadsheetApp` / `DriveApp` / `UrlFetchApp` と同じ**組み込みサービス**なので、エディタの「サービス」から追加する必要はない。「サービス」に並ぶ `Drive` や `Docs` は**高度なGoogleサービス**（`appsscript.json` の `enabledAdvancedServices`）で、別物。

### 権限（スコープ）の扱い
- `appsscript.json` に `oauthScopes` を書いていなければ、スコープは**自動検出**される。`CalendarApp` を使うコードを足すと、カレンダーのスコープが増える。
- 明示的に `oauthScopes` を書くと自動検出が無効になり、他のスコープが足りなくなって壊れることがあるので、安易に書かない。
- スコープが増えたら、**GASエディタで任意の関数を1回手動実行して再認可**する。しないと、時間主導トリガーが権限エラーで失敗する。時間主導トリガーはHead（最新コード）で動くので、`clasp push` した直後の次の実行から新しいコードになる点にも注意。
- 再認可の確認用の関数（`console.log(isBusinessDay_(new Date(2026, 10, 3)))` など）をエディタで試すには、確認したい関数が既にGAS側にある必要がある。つまり**先に `clasp push` が必要**。

## 3. 判定ロジックを1つの関数に集約する

### 何が問題だったか
「その日は営業日か」という同じ問いに対して、次の3か所がそれぞれ別に `getDay()` で答えていた。

1. 今日が平日かを返す関数（引数なし。常に「今日」を見る）
2. 文字列で渡された対象日が平日かを返す関数
3. 経過営業日数を数えるループの中の `getDay()`

このままだと、祝日対応に3か所の修正が必要になる。さらに、1.は引数を取らないので、ループの中の日付には使えなかった。そのため3.は直書きになっていた。

### 解決: `Date` を引数に取る関数にする
```javascript
function isBusinessDay_(date) {
  const dayOfWeek = date.getDay();
  if (dayOfWeek === 0 || dayOfWeek === 6) return false;  // 土日
  return !isJapaneseHoliday_(date);                      // 祝日
}

isBusinessDay_(new Date())                      // 今日
isBusinessDay_(parseDateString_(dateString))    // 文字列の対象日
isBusinessDay_(cursor)                          // ループ内の日付
```

- 判定が**引数の日付で決まる**関数にすると、「今日」「文字列の対象日」「ループ内の日付」のどれにも使い回せる。
- 判定ロジックが1か所になるので、祝日の取得方法を変えるときも直す場所が1つで済む。
- 使われなくなった旧関数は、呼び出し元が無ければ削除する。

### 「対象日」で判定する意味（0件通知の例）
「会議の文字起こしが0件だったら警告を出す。ただし休日は会議が無くて当たり前なので警告しない」という処理がある。

```javascript
if (shouldNotify && isBusinessDay_(対象日)) {
  警告を出す;   // 営業日(true)のときだけ警告
}
```

読み方に注意が必要で、`true`（営業日）は「警告を出す」という意味になる。

- 昔の運用では「実行日の前日」が対象日だった。月曜の実行では対象日が日曜になる。
- このとき「今日」で判定すると、月曜（営業日）なので警告が出てしまう。実際は日曜に会議が無いのは正常なので、誤報になる。
- 対象日で判定すれば、日曜は休日なので警告は出ない。

現在は「対象日＝実行当日」の運用に変わったため、今日で判定しても結果は同じ。それでも、日付を引数に取る形にしておけば、運用が変わって対象日が今日とずれても壊れない。

## 4. 実装上の注意点

### ループ内から呼ばれるので、カレンダーへの通信を最小にする
営業日数を数える処理は「対象の行ごと × 経過日数ごと」に判定関数を呼ぶ。日付ごとにカレンダーへ問い合わせると通信回数が「行数 × 日数」になり、実行が遅くなる。

- **年単位で1回だけ取得**し、結果を `Set` にして**実行中のグローバル変数にキャッシュ**する（GASのグローバル変数は実行ごとに初期化されるので、実行をまたいだ古いキャッシュが残る心配はない）。
- **土日は曜日だけで決まる**ので、先に曜日で判定して `return` する。土日の判定にはカレンダーへの通信を発生させない。

### 取得に失敗したときの方針
カレンダーの取得失敗で投稿やリマインド自体が止まるより、従来どおり土日のみの判定で動き続ける方がよいと判断した。

- 例外を投げず、警告ログを出して空の `Set`（祝日なし）を返す。
- 失敗した結果も、同じ実行中はキャッシュする（何度も再試行しない）。
- 代わりに「失敗した回は祝日でも投稿・リマインドが出うる」という副作用がある。ログの警告で気づけるようにしておく。

これは「失敗時に止めるか（fail-close）、続けるか（fail-open）」の判断で、今回は処理の継続を優先した。

## 5. 検証のしかた

- **Nodeでロジックを検証**: `CalendarApp` や `Utilities` をモックし、`vm` モジュールで該当ファイルを読み込んで関数を呼ぶ。GASのコードは `require` などを使っていないので、そのまま実行できる。
  - 確認した観点: 平日・土日・祝日・祝日の翌日、土日だけなら通信しないこと、同じ年は何度呼んでも通信が1回であること、祝日を挟んだときの営業日数、取得失敗時のフォールバックと警告ログ。
  - 検証用のスクリプトはプロジェクトに入れず、一時ディレクトリで実行して削除した。
- **実機（GASエディタ）で確認**: 一時的な確認用の関数を作り、祝日（例: 11/3の文化の日）が `false` になることをログで確認する。警告が出ていなければ、カレンダーの取得も成功している。

## 6. 仕様変更として波及する点

祝日を判定に含めると、次のように挙動が変わる。実装前に洗い出しておき、コメントやドキュメントも合わせて直す。

- 祝日は、投稿とリマインドが止まり、次の営業日にまとめて出る。
- 経過営業日数が、祝日を挟むとその分少なくなる（初回リマインドが遅れる）。
- 0件警告は、祝日には出ない。
- 「祝日は考慮しない」と書いてあったコメントやREADMEは、更新漏れが起きやすい。`grep` で関数名や「祝日」を検索して直す。

## まとめ

- GASで祝日を判定するなら、Googleカレンダー「日本の祝日」を `CalendarApp` で参照するのが定番。組み込みサービスなので「サービス」への追加は不要で、初回の権限承認だけ必要。
- 営業日の判定は、`Date` を引数に取る関数1つに集約すると、「今日」「文字列の対象日」「ループ内の日付」のどこからでも使い回せる。
- ループ内から呼ばれる関数では、祝日を年単位で1回だけ取得して実行中キャッシュし、土日は曜日で先に判定してカレンダーへの通信を避ける。
- 取得失敗時は、止めずに土日のみで続行し、警告ログで気づけるようにする。
- 判定が「今日」か「対象日」かで結果が変わる場面（実行日と対象日がずれる運用）を意識して、日付を引数に取る形にしておく。
- スコープが増えたら、`clasp push` のあとにGASエディタで手動実行して再認可する。時間主導トリガーはHeadで動くため、再認可前に次の実行が来ると失敗しうる。
